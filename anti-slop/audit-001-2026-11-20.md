## Findings

### 1. [user] The A+/A− control zooms the whole UI, not just the lyrics — HIGH (R-39, C-4)

`styles.css:11-14` sets `html { font-size: calc(100% * var(--font-scale)) }`. `viewer.js:193` writes `--font-scale` (0.75 to 1.5) onto `<html>`, so every `rem` in the product multiplies: the back button, the tabs, the badges, the headings. The control's accessible name is "Increase text size" and it sits in the lyrics transport, so it promises one thing and does another.

Fix: drop the root rule and multiply only the lyric line, `font-size: calc(var(--lyrics-size) * var(--font-scale))` on `.lyric-line`. CSS only, no wiring change, browser zoom untouched.

Note: this behaviour is inherited from the pre-redesign stylesheet, not introduced by the redesign.

### 2. [user] Buttons read as too basic — LOW (R-11), user-named

Every control is a full pill: `.btn` (133), `.badge` (232), `.chip` (645), `.tab` (105), `.tabbar` (89), `.progress`. Only the search input breaks it, and only because it is square. The uniform pill is Spore's declared control system, so this collides with the dealt theme and is yours to override (R-37).

Options, pick one or combine:
- **(a)** moderate radius on buttons (~10px), pills kept for chips and badges only.
- **(b)** hierarchy instead of shape: primary taller with more padding, secondary quieter (border in `--color-rule` rather than `--color-ink-2`).
- **(c)** both.

### 3. [user] The font on the lists — MEDIUM (R-06), user-named

Young Serif carries `.song-title` (425), `.result-title` (697) and `.pack-artist` (327). On 34 song rows and a result list it slows scanning and reads heavier than the content deserves.

Fix: lists in Instrument Sans at 1.1 to 1.2rem; keep Young Serif for screen headings (wordmark, pack name, Search, viewer title) and, if you like it there, the pack artist. The identity stays where a title is read as a title.

### 4. [user] The colour combination — MEDIUM (R-29, R-01), user-named, needs a steer

Current: ground `oklch(15% 0.012 60)` warm brown-black, ink parchment `oklch(93% 0.022 85)`, muted brown-grey `oklch(67% 0.02 70)`, one oyster pink `oklch(77% 0.09 30)`.

Three different complaints hide under this one. Which is it?
- **(a)** the pink reads dusty or fleshy rather than a signal → raise its chroma or shift the hue toward red.
- **(b)** everything is brown (ground, rules, muted text, labels) and feels muddy → cool the neutrals while keeping the warm ground.
- **(c)** the light scheme specifically.

### 5. `cursor: pointer` is not set in a base layer — HIGH (R-39)

`.btn`, `.song-row`, `.chip` and `.result-row` each set it individually. `.tab` (105) and `.speed input[type=range]` do not, and there is no rule at all for `a[href]`, `summary`, `select`, `label[for]`, which R-39 requires set once in the base layer. The pre-redesign stylesheet had exactly that block, with a comment citing R-39; the rewrite dropped it.

Fix: restore the base block once, delete the four per-component duplicates.

### 6. Click-through is not recorded for every control — HIGH (R-35)

Recorded so far, all with a clean console: pack download → badge, Open → program, song → viewer, auto-scroll Start and Pause, search submit → results, offline reload → offline banner, light scheme emulated.

Not exercised: Delete two-tap confirm, A− and A+, speed − and +, Prev and Next, recent-query chips, tab switch, skip link.

Fix: run the full list and record it element by element.

### 7. A failed IndexedDB read leaves a permanent skeleton or a stale screen — HIGH (R-27, C-4)

Loading and empty states exist everywhere (skeletons, online/offline empty variants, "not on this device", "no lyric text", "no matches", download failure with a reason). What is missing is the error path: `app.js:87` `refreshDownloaded()`, `app.js:196` and `app.js:228` `store.getPack()` are uncaught. If IndexedDB rejects, the home and program screens sit on their skeleton forever and the viewer keeps the previous screen with no message.

Fix: catch, then render an error state that says what broke and what to do. This adds logic to `app.js`, so it needs your approval as a code change, not just a style change.

### 8. The dose-cap reasons live in this audit, not in the source — LOW (R-31)

Glass (one element: the tab pill), shadow (two: tab pill, snackbar), the grain on the transport, and the skeleton pulse all pass their caps, but nothing in the CSS says why. R-31 wants the one-line reason next to the decision.

Fix: a comment at each declaration.

### 9. No `<header>` landmark at document level — LOW (R-39)

`index.html` carries `nav` and `main` only. On an app shell a document-level `header` would be empty chrome, so dismissal is defensible; listed so the call is yours.

## The re-pitched palette

Ground `oklch(14% 0.008 65)` (#0b0806), ink `oklch(95% 0.01 90)` (#f1eee7), one accent `oklch(66% 0.18 25)` (#ec5b57). The neutrals lost their brown so the page reads as charcoal rather than mud, and the accent went back to the project's own warm red at signal chroma. Light scheme follows: bone paper, deep signal red, hover darkens rather than lightens so the label keeps 4.5:1. `icon.svg`, `manifest.webmanifest` and the `theme-color` meta follow the ground.

## Open, for the owner (not fixed: outside the approved numbers)

- **Skip link sets `hash #main`.** Pressing it from any screen other than home routes to home, because the router treats an unknown hash as the packs view. Pre-existing wiring from before the redesign; the focus move itself works. Fix would be `href="#main"` plus the router ignoring `#main`, or a `preventDefault` that only focuses `#main`.
- **Three uncaught awaits remain** at `app.js` after download, after delete and at the top of `runSearch`. They cannot strand a screen the way the three fixed ones could, but they are the same class of defect.
- **`app/README.md` "Layout notes"** still describes the pre-redesign typography (system stack, Mochy focus ratios, the old opacity floor). Documents are not page copy, so it was left alone.
